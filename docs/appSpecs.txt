1. Overview
CarHunter is a mobile game built around the real-world hobby of car spotting. Users photograph cars they encounter in their daily life and earn XP, level up, unlock trophies, and complete challenges based on what they find and where they find it. The app is designed for anyone -- not just car enthusiasts -- to discover a new hobby and build a competitive, engaging game around it. The core loop is simple: go outside, spot a car, photograph it through the in-app camera, receive an AI-powered identification with a contextual XP score, and watch your rank grow. The more unusual the car and the more unexpected its location, the more XP you earn. CarHunter is built for iOS using React Native with Expo, backed by a FastAPI backend that orchestrates a third-party AI vision API for car identification and runs a custom XP scoring engine.
2. Product Vision & Goals
2.1 Target Audience

Primary: Car enthusiasts aged 20-30 who already photograph interesting cars and want a game layer on top of that hobby. Secondary: Anyone curious about cars who wants an excuse to explore their surroundings and discover a new interest.
2.2 Core Value Proposition
· Real-world exploration game -- XP comes from getting outside and finding cars, not from knowledge or grinding
· Contextual scoring -- a rare car in an unexpected location scores more than a rare car in an obvious one
· Discovery mechanics -- the first time you spot a car model is always more rewarding than repeat spots
· Global by design -- the location scoring system rewards users everywhere, not just in wealthy car-dense cities
2.3 Revenue Model
· Free tier: Core camera spotting, XP, basic leveling, garage · One-time purchase ($8.99): Unlocks a specific premium feature (TBD) · Subscription ($4.99/month): Rarity XP bonuses, advanced challenges, leaderboards, full
profile customisation

5. System Architecture
5.1 High-Level Flow
The following describes the complete data flow for a single car spot -- the core game loop:
 User takes photo in-app camera 
 React Native app sends image + context (location, user_id, condition, is_modified) to FastAPI /identify
  FastAPI calls third-party AI Vision API  receives make, model, trim, year, specs, colour
  FastAPI runs XP scoring engine (base XP × location × condition × modifications × photo quality × first encounter)

  FastAPI queries Supabase to check if this is a first encounter for this user_id + car model
  Full response returned to app: car details, specs, XP breakdown, final XP total
  User reviews result, adds notes, additional photos, then saves
  Spot saved to Supabase. XP added to user profile. Congrats screen shown.

5.3 API Communication
All API calls are handled through a dedicated carIdentificationService.ts service layer. The app never calls the API directly from a screen or store. This separation makes it easy to swap the backend URL or mock responses during testing.

7.2 Contextual Multipliers
Location (assessed by GPT-4o)
Context Strongly boosts rarity -- supercar in Singapore, exotic in rural/developing area Moderately boosts rarity -- exotic outside a major wealth hub Neutral -- expected for this car tier and location

Multiplier 1.8x
1.4x 1.0x

Location only ever boosts, never penalises. The floor is 1.0x. GPT-4o assesses this using car tier + location name and returns: high, moderate, or neutral.

Condition (user-selected)
Condition Pristine Good (default) Fair Beater

Multiplier 1.3x 1.0x 0.85x 0.7x

Modifications (user-selected flag)
State Modified / tuned Stock (default)

Multiplier 1.25x 1.0x

Photo Quality (assessed by GPT-4o)
Quality High -- sharp, well-framed, full car visible Medium -- acceptable, minor issues Low -- blurry, partial, poor lighting

Multiplier 1.2x 1.0x 0.8x

First Encounter (backend-checked)
State First time spotting this car model Already spotted before

Multiplier 1.5x 1.0x

First encounter is checked by querying the user's Supabase history. It is applied last, after all other multipliers, and sits outside the multiplier cap.

7.3 Multiplier Cap
The total multiplier (excluding first encounter) is capped at 3.5x. First encounter always applies on top of the cap.
Maximum possible XP: 1200 × 3.5 × 1.5 = 6,300 XP (perfect first-time Legendary spot)

14. Key Design Decisions & Rationale
· Third-party AI API over custom model: Faster to launch, no GPU inference costs, easier to swap. Trade-off is per-request cost at scale.
· XP only from in-app camera: Prevents cheating via internet image uploads while keeping the experience clean for genuine users.
· Legacy spots at onboarding only: Rewards existing enthusiasts fairly without opening an ongoing cheating vector.
· First encounter outside the multiplier cap: Ensures genuinely momentous discoveries (first Legendary spot) are never dampened by the cap.
· Location multiplier floors at 1.0x: Never penalises users for where they live -- only rewards unusual finds.
· GPT-4o for location and photo quality assessment: Scales infinitely, handles edge cases naturally, no hardcoded city lists required.
· Zustand over Redux: Simpler API, less boilerplate, sufficient for this app's state complexity.
· Monorepo structure: Keeps backend, mobile, and ML code in sync with a single git history.
